每日日报

一条 SQL 出 9 个指标：当日注册、绑卡、新客首投、新客交易、当日交易总额，再加三项累计。基于 p2p_learning 库，按 MySQL 8 默认模式（ONLY_FULL_GROUP_BY 开启）可直接执行。

MySQL 8.0.39 实测通过 9 指标 34 个渠道 两版结果逐行一致

WHERE biztype IN (1, 3)   -- 理财 + 点点宝

  AND `status` = 20       -- 成功

01这条日报是什么

原始模板用 9 层 LEFT JOIN 把渠道维度摊成一张日报，但只写到第 4 段、且按 MySQL 5.x 的非严格模式写的。本页把 9 个指标补全，并给出两版都能在 MySQL 8 上跑的写法。

9个指标 · 当日 6 + 累计 3
5处语法坑 · 其中 3 处直接 1055
3处口径坑 · 数字会错但不报错
34行2016-01-26 实测渠道数

两种写法，结果一致。主版本用 CTE，每个指标先聚到 channel 唯一再 JOIN，加指标只需加一段；保骨架版保留 xxx + aaa..iii 的 9 层 LEFT JOIN，用来和原脚本逐段对照。两版 34 行、10 列全部逐值相同。

02怎么跑起来

只需要改日期。库名、表名、字段名都已按 schema.sql 对齐，不依赖 v2 补全脚本新增的列。

先改一处库名。v2_数据补全.sql 第 7 行写的是 USE tianchi_userbehavior;，那是从原天池脚本带过来的遗留，库实际叫 p2p_learning。不改直接跑会报 Unknown database。

导数据的字符集。命令行导入 data.sql 时加 --default-character-set=utf8mb4，否则 Windows 默认 GBK 会在 itemtitle 上报 ERROR 1366。

039 个指标的口径

列名直接按原模板的占位符顺序：前 4 个模板已给定义，后 5 个（eee / fff / ggg / hhh / iii）在原模板里能看到注释，按注释还原。

#列名口径取数易错
01当日注册人数registtime 落在日报日accountdate() 包列索引失效
02当日绑卡人数绑卡成功 status=20account_independent_authentication别用充值代替，实测差 5.8 倍
03当日新客数当日有成功投资 且 此前从未成功投资da_account_tradeNOT IN 遇 NULL 整列变空
04新客首投金额每人取当日第一笔da_account_trade原模板取的是"任意一笔"
05新客交易额新客当日全部成功投资da_account_trade与 04 的差 = 当日多笔部分
06当日交易总额新老客全量da_account_trade四列相加，漏 assetamount 会低估
07累计注册人数registtime < @cum_endaccount原模板写死 01-29，与日报日错位
08累计交易人数累计去重人数da_account_tradecount(*) 必须先按人去重
09累计交易总额createtime < @cum_endda_account_trade同 06 的四列相加

「累计」截止日统一取 @cum_end = @dt + 1 天，即累计到日报日结束。想改成"截至昨日"，把它设成 @dt 即可。

04主版本：CTE

参数 + 6 段 CTE + 一次 LEFT JOIN。每个 CTE 已经聚到 channel 唯一，所以不会放大行数；没有数据的渠道用 COALESCE 显示 0，导 Excel 后直接求和不会报错。

channel_daily_cte.sql
-- 0. 参数：只改这三行
-- ------------------------------------------------------------
SET @dt      = '2016-01-26';                        -- 日报日期
SET @dt_end  = DATE_ADD(@dt, INTERVAL 1 DAY);        -- 当日右边界（半开区间）
SET @cum_end = DATE_ADD(@dt, INTERVAL 1 DAY);        -- 累计截止（原模板写死 '2016-01-29'）

-- 1. 主版本（推荐）：CTE，每个指标先聚到 channel 唯一，再 LEFT JOIN
--    优点：① 不踩 ONLY_FULL_GROUP_BY ② 每个子集只扫一遍表
--          ③ 没有数据的渠道显示 0 而不是 NULL ④ 加指标只需加一个 CTE
-- ############################################################
WITH ch AS (                                  -- 渠道全集：取注册主表，不用 da_ 日增量
    SELECT DISTINCT channel
    FROM account
    WHERE channel IS NOT NULL AND channel <> ''
),
reg AS (                                      -- ① 当日注册人数
    SELECT channel,
           COUNT(*) AS reg_cnt
    FROM account
    WHERE registtime >= @dt AND registtime < @dt_end
    GROUP BY channel
),
card AS (                                     -- ② 当日绑卡人数（绑卡事实表，status=20 成功）
    SELECT a.channel,
           COUNT(DISTINCT t.accountid) AS card_cnt
    FROM account_independent_authentication t
    JOIN account a ON a.id = t.accountid
    WHERE t.`status` = 20
      AND t.createtime >= @dt AND t.createtime < @dt_end
    GROUP BY a.channel
),
day_tx AS (                                   -- 当日每个用户的交易笔数 / 合计金额 / 首笔金额
    SELECT x.accountid,
           COUNT(*)                                        AS tx_cnt,
           SUM(x.amt)                                      AS day_amt,
           SUM(CASE WHEN x.rn = 1 THEN x.amt ELSE 0 END)   AS first_amt
    FROM (
        SELECT t.accountid,
               t.tradeid,
               (t.amount + t.assetamount + t.bonusamount + t.couponamount) AS amt,
               ROW_NUMBER() OVER (PARTITION BY t.accountid
                                  ORDER BY t.createtime, t.tradeid)        AS rn
        FROM da_account_trade t
        WHERE t.biztype IN (1, 3)              -- 1=优选理财 3=点点宝
          AND t.inouttype = 1                  -- 1=流入
          AND t.`status` = 20                  -- 20=成功   ← 黄金组合
          AND t.createtime >= @dt AND t.createtime < @dt_end
    ) x
    GROUP BY x.accountid
),
new_user AS (                                 -- ③④⑤ 当日新客：当日有交易 且 当日之前从未成功投资
    SELECT d.accountid, d.tx_cnt, d.day_amt, d.first_amt
    FROM day_tx d
    WHERE NOT EXISTS (
            SELECT 1
            FROM da_account_trade h
            WHERE h.accountid = d.accountid
              AND h.biztype IN (1, 3)
              AND h.inouttype = 1
              AND h.`status` = 20
              AND h.createtime < @dt
          )
),
new_by_ch AS (                                -- 新客三个指标聚合到渠道
    SELECT a.channel,
           COUNT(*)          AS new_cnt,       -- ③ 新客交易人数
           SUM(n.first_amt)  AS first_amt,     -- ④ 新客首次交易金额
           SUM(n.day_amt)    AS new_amt        -- ⑤ 新客交易金额（当日合计）
    FROM new_user n
    JOIN account a ON a.id = n.accountid
    GROUP BY a.channel
),
all_by_ch AS (                                -- ⑥ 当日交易总额（新老客）
    SELECT a.channel,
           COUNT(DISTINCT t.accountid) AS trade_cnt,
           SUM(t.amount + t.assetamount + t.bonusamount + t.couponamount) AS trade_amt
    FROM da_account_trade t
    JOIN account a ON a.id = t.accountid
    WHERE t.biztype IN (1, 3)
      AND t.inouttype = 1
      AND t.`status` = 20
      AND t.createtime >= @dt AND t.createtime < @dt_end
    GROUP BY a.channel
),
cum_reg AS (                                  -- ⑦ 累计注册人数
    SELECT channel,
           COUNT(*) AS cum_reg_cnt
    FROM account
    WHERE registtime < @cum_end
    GROUP BY channel
),
cum_trade AS (                                -- ⑧⑨ 累计交易人数 / 累计交易金额
    SELECT a.channel,
           COUNT(DISTINCT t.accountid) AS cum_trade_cnt,
           SUM(t.amount + t.assetamount + t.bonusamount + t.couponamount) AS cum_trade_amt
    FROM da_account_trade t
    JOIN account a ON a.id = t.accountid
    WHERE t.biztype IN (1, 3)
      AND t.inouttype = 1
      AND t.`status` = 20
      AND t.createtime < @cum_end
    GROUP BY a.channel
)
SELECT
    ch.channel                             AS 渠道,
    COALESCE(reg.reg_cnt, 0)               AS 当日注册人数,
    COALESCE(card.card_cnt, 0)             AS 当日绑卡人数,
    COALESCE(nc.new_cnt, 0)                AS 当日新客数,
    COALESCE(nc.first_amt, 0)              AS 新客首投金额,
    COALESCE(nc.new_amt, 0)                AS 新客交易额,
    COALESCE(ac.trade_amt, 0)              AS 当日交易总额,
    COALESCE(cr.cum_reg_cnt, 0)            AS 累计注册人数,
    COALESCE(ct.cum_trade_cnt, 0)          AS 累计交易人数,
    COALESCE(ct.cum_trade_amt, 0)          AS 累计交易总额
FROM ch
LEFT JOIN reg       ON reg.channel      = ch.channel
LEFT JOIN card      ON card.channel     = ch.channel
LEFT JOIN new_by_ch nc ON nc.channel     = ch.channel
LEFT JOIN all_by_ch ac ON ac.channel     = ch.channel
LEFT JOIN cum_reg   cr ON cr.channel     = ch.channel
LEFT JOIN cum_trade ct ON ct.channel     = ch.channel
ORDER BY 2 DESC, 1 ASC;      -- 当日注册人数倒序，同数按渠道名
主版本：参数 + CTE + 一次 LEFT JOIN，可直接整段执行

为什么用 CTE 而不是 9 层 JOIN。同一张 da_account_trade 在骨架版里被扫了 5 遍（新客人数、首投金额、新客金额、当日金额、累计人数、累计金额），CTE 版可以合并到 2 遍。new_user 那段把「当日有没有交易」和「历史上有没有交易」拆成两层，是为了让 ROW_NUMBER 只跑一次。

05保骨架版：9 层 LEFT JOIN

结构与原模板一模一样：xxx 做渠道全集，aaa..iii 依次挂 9 个指标。只改报错和口径，不改结构，方便和老脚本一行一行对照。

    IFNULL(aaa.reg_cnt, 0)               AS 当日注册人数,
    IFNULL(bbb.card_cnt, 0)              AS 当日绑卡人数,

FROM
    (SELECT DISTINCT channel
     FROM account
     WHERE channel IS NOT NULL AND channel <> '') xxx

06总量对账

日报上线前跑一次：这 7 个全表直算值，必须分别等于上面各列的纵向求和。差一个数就说明某列少算或重复算了。

reconcile.sql
-- 3. 总量对账：一行结果，必须等于上面各列纵向 SUM
--    日报上线前跑这一条，能立刻抓出"某列少算 / 某列重复算"
-- ############################################################
SELECT
    (SELECT COUNT(*)
       FROM account
      WHERE registtime >= @dt AND registtime < @dt_end)                 AS 当日注册人数,
    (SELECT COUNT(DISTINCT accountid)
       FROM account_independent_authentication
      WHERE `status` = 20
        AND createtime >= @dt AND createtime < @dt_end)                 AS 当日绑卡人数,
    (SELECT COUNT(DISTINCT accountid)
       FROM da_account_trade
      WHERE biztype IN (1,3) AND inouttype = 1 AND `status` = 20
        AND createtime >= @dt AND createtime < @dt_end)                 AS 当日交易人数,
    (SELECT SUM(amount + assetamount + bonusamount + couponamount)
       FROM da_account_trade
      WHERE biztype IN (1,3) AND inouttype = 1 AND `status` = 20
        AND createtime >= @dt AND createtime < @dt_end)                 AS 当日交易总额,
    (SELECT COUNT(*)
       FROM account
      WHERE registtime < @cum_end)                                      AS 累计注册人数,
    (SELECT COUNT(DISTINCT accountid)
       FROM da_account_trade
      WHERE biztype IN (1,3) AND inouttype = 1 AND `status` = 20
        AND createtime < @cum_end)                                      AS 累计交易人数,
    (SELECT SUM(amount + assetamount + bonusamount + couponamount)
       FROM da_account_trade
      WHERE biztype IN (1,3) AND inouttype = 1 AND `status` = 20
        AND createtime < @cum_end)                                      AS 累计交易总额;
7 个全表直算值，与各列纵向求和比对

本库 2016-01-26 的对账结果：注册 32、绑卡 35、当日交易人数 31、当日交易总额 67,984.24、累计注册 10,840、累计交易人数 4,749、累计交易总额 43,695,791.45，与分渠道求和全部相等。

08原模板 5 个语法坑

前 3 条在 MySQL 8 默认模式下直接报 1055，第 4 条会让整列变空，第 5 条只是慢。以下报错都是本机 8.0.39 实跑出来的原文。

  1. ddd 子查询：多列 + GROUP BY 11055
    原写法 SELECT accountid, amount, assetamount, ... GROUP BY 1，只有 accountid 在 GROUP BY 里。
    ERROR 1055: Expression #2 of SELECT list is not in GROUP BY clause and contains nonaggregated column 'p2p_learning.da_account_trade.amount'
    改法：按人 SUM() 聚合，首笔用 ROW_NUMBER() OVER (PARTITION BY accountid ORDER BY createtime, tradeid) = 1。
  2. hhh 子查询：同一个写法1055
    累计交易人数也是 SELECT accountid, amount, ... GROUP BY 1。改法：直接 COUNT(DISTINCT accountid)，语义等价且合法。
  3. 最外层 GROUP BY 11055
    SELECT xxx.channel, aaa.count, ... GROUP BY 1，其余 9 列都是派生表列、不是聚合函数，MySQL 8 会拒绝：... contains nonaggregated column 'aaa.cnt'。而且每个子查询已经按 channel 唯一，这个 GROUP BY 本来就不需要，删掉即可。
  4. NOT IN (子查询)逻辑
    子查询里只要有一行 accountid IS NULL，NOT IN 恒为 UNKNOWN，整个条件变空、新客数直接归零，而且不报错。改 NOT EXISTS 或 NOT IN (... WHERE accountid IS NOT NULL)。
  5. date(createtime) = '2016-01-26'性能
    函数包住索引列，idx_time 用不上，全表扫。改半开区间 createtime >= @dt AND createtime < @dt + INTERVAL 1 DAY，结果完全一样。

11口径说明

对外解释这张表时可以直接抄的部分。

  • 渠道归因：全部按注册渠道 account.channel。不要混用 da_account_trade.channel，那是交易发生渠道，两者不同源。
  • 当日：[dt, dt+1) 半开区间，不写 DATE(createtime)=dt。
  • 新客：当日有成功投资，且该用户历史上没有成功投资。「历史上」用 < @dt，不含当日，所以当日多笔仍算新客。
  • 首投金额：该用户当日第一笔（按 createtime, tradeid 排序）的金额；新客交易额是该用户当日全部成功投资金额。
  • 人数：全部 COUNT(DISTINCT accountid)，一人多笔只算 1 人。
  • 金额：amount + assetamount + bonusamount + couponamount 四列相加。点点宝余额支付走 assetamount，漏掉会低估。
  • 重叠不算错：同一用户当日既注册又首投，会同时进「注册人数」和「新客数」，漏斗指标允许重叠。
