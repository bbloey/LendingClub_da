一周作战计划

目标不是"跑完 27 条 SQL"，而是一周后手里有一份能放进作品集的经营分析报告：日报、月报、年报各一份，配一套 Power BI 看板，外加一段能写进简历的项目描述。基于 p2p_learning 库，2 万用户 / 20 个月。

01这周要交出什么

先说清优先级。你要的是"找到数据分析师工作"，所以判断标准只有一个：面试官看到这份东西，会不会认为你干过真实的经营分析。SQL 写得再花，报告讲不出结论，价值减半。

1份主报告 · 15–20 页 PDF
3层日 / 月 / 年三个粒度
1套Power BI · 3 页看板
6类数据质量校验 SQL

三层报告的分工，别写成三份一样的。日报回答「昨天发生了什么」，是监控；月报回答「这个月和上个月哪里不一样」，是结构；年报回答「这一年我们做对了什么、错在哪」，是叙事。三份报告的分析方法完全不同，这也正是面试官想看的区分度。

先接受一个前提：这份数据的样本量撑不起"日报"。2 万用户摊到 609 天，日均注册约 33 人，单渠道日均不到 1 人。所以 Day 2 的日报重点是报表结构与口径，不是业务结论；真要看趋势，用周或月做窗口。在报告里主动写清这一点，反而是加分项——说明你知道粒度和样本量的关系。

02一周时间表

每天三块：上午写 SQL（2 小时）、下午出报告（2.5 小时）、晚上复盘（30 分钟）。周末两天用来整合和打磨，不安排新内容。

03每天固定动作

比任务本身更重要的是这个节奏，它决定你能不能在一周后还有力气整合。

  • 开工 10 分钟：把当天要交的 3 个文件写在纸上，贴屏幕边。写完一条划一条。
  • 收工 10 分钟：写三行——今天学会了什么、卡在哪、明天第一件事做什么。这三行是 Day 7 复盘的原料。
  • 遇到卡壳 20 分钟规则：一个问题卡超过 20 分钟就记下来跳过，别让它吃掉整块时间。晚上统一查。
  • 不留未保存的 SQL：所有写过的查询都存成文件，哪怕是废稿。报告里的每个数字后面都要能追到一条 SQL。
Day 1

地基：先证明数据能不能用

今天不产出任何业务结论，只做一件事——搞清楚这份数据哪些能信、哪些不能信，并把时间因果修好。

昨天我们已经查出来：84.7% 的投资用户，首投时间早于注册时间（中位差 −203 天），根因是 gen_data.py 第 178 行把交易时间按全局随机撒了，没绑注册日。不修这个，你后面三份报告里所有"转化"类指标全是错的。

时段任务产出
09:00–09:30建库导入，跑通 3 条探索查询（月度注册 / 全站漏斗 / 12-31 留存）库就绪
09:30–11:00写 6 类数据质量校验 SQLdata_quality_check.sql
11:00–12:00改 gen_data.py 三处，重跑重导data_v2.sql
14:00–15:30复测：6 类检查全部归零复测结果截图
15:30–17:00写《数据质量体检报告》一页体检报告.md
20:00–20:30业务思考题笔记三行
SQL 练习 · 不看答案自己写
  1. 找出「首次成功投资时间早于注册时间」的用户数，以及时间差的中位数。提示：先取每人 MIN(createtime)，再和 registtime 比。
  2. 统计绑卡表里 createtime > '2016-08-31' 的记录数。再查 account_partner_trade 的日期范围。这两个越界要出现在你的体检报告里。
  3. 同一件事两套口径：account_independent_authentication 里的绑卡人数 vs account.iDdate IS NOT NULL 的人数，差多少？哪个更可信、为什么？
  4. 找出交易表里 accountid 不在 account 表的孤儿记录（用 LEFT JOIN ... IS NULL 和 NOT EXISTS 各写一遍，比较执行计划）。
  5. 检查金额异常：amount <= 0、四列金额全为 0、以及 amount > 1000000 的记录各有多少条。
  6. 勾稽检查：取 2016-08-31 的余额快照总和，和「累计充值 − 累计提现 − 累计投资 + 累计回款」比，差多少？解释为什么对不上。

修数据只改三处，别重写整个脚本。① 交易 createtime = 注册时间 + 随机的 0–45 天（首投），后续笔数按 15–90 天间隔累加；② 回款日期 = 投资日 + selfitem.totalperiods 对应的天数，不再固定 +90；③ 渠道按质量分三档给不同的首投率（应用商店高、信息流低）。改完重跑 python gen_data.py，重新导入。

业务思考

老板问：「我们 2 万注册用户里有 26% 投资了，这个转化率可信吗？」你要能在 30 秒内答出三件事：分子分母各是什么、哪张表是权威来源、这个数在行业里算高还是低。想清楚再往下做——这份答案会直接变成你报告里「数据说明」那一节。

今日交付物
  • 01_体检/data_quality_check.sql——6 类检查，每类一条 SQL，注释写清预期值和实际值
  • 01_体检/数据质量体检报告.md——一页：发现的 5 个问题、影响哪些指标、怎么处理
  • 修复后的 p2p_learning 库（重跑过的 data.sql）
  • 当晚三行复盘

今天这份体检报告，是你整周最容易被面试官记住的东西。大部分候选人的项目是"我写了 SQL 得出 XX 结论"；你能说"我接手后发现首投时间有 85% 早于注册时间，定位到是生成脚本没绑关联键，修复后重算"——这句话证明你懂数据是怎么来的，而不只是会查。

Day 2

日报：每天必看的 9 个数

把 9 指标日报从零写一遍（不许看现成答案），然后做成一张能每天填的模板。

昨天修完数据，今天第一件事是合上之前那份 渠道明细日报_9指标.sql，自己重写。写不出来再看，看的时候重点看它为什么用 CTE 而不是 9 层 JOIN。

时段任务产出
09:00–10:30不看答案重写 9 指标日报daily_report.sql
10:30–12:00加环比列（对比昨日），两版写法比对含 MoM 的版本
14:00–15:30做日报模板（Excel），含异常标注规则日报模板.xlsx
15:30–17:00跑 3 天（平日 / 双十二 / 月末）并写当日结论3 份日报
20:00–20:30业务思考题笔记三行
SQL 练习 · 不看答案自己写
  1. 9 个指标：当日注册、当日绑卡、当日首投人数、首投金额、当日交易额、当日交易人数，加累计注册、累计交易人数、累计交易额。每人金额统一用 amount + assetamount + bonusamount + couponamount。
  2. 给每个指标加「较昨日」列。用 LAG(...) OVER (ORDER BY stat_date)，先把日报跑成一张按日汇总的表，再在外面套一层窗口函数。
  3. 算「注册 → 绑卡 → 首投」三级转化率，分母统一用当日注册人数。注意分母不能用「当日绑卡人数」，否则分子分母不同源。
  4. 找出当日「注册且当天首投」的用户，他们贡献了多少交易额？占比多少？这才是渠道质量的真实信号。
  5. 给日报加一个异常标记列：任一指标环比波动超过 ±30% 就标 1。想想为什么阈值要按指标分开设，而不是都设 30%。
业务思考

9 个指标里如果只能留 3 个，你留哪 3 个？说清楚各自的“看什么、异常了怎么办”。这道题在面试里几乎必问，因为它考的是你有没有真的每天看数——而不是会不会写 SQL。

今日交付物
  • 02_日报/daily_report.sql——自己写的版本，和之前那份对比差异
  • 02_日报/日报模板.xlsx——表头 + 3 天样例 + 异常标注规则说明
  • 3 天的日报结果，每份配一句话结论（不超过 40 字）

写结论时管住手。日均注册 33 人，单渠道不到 1 人，"某渠道今日注册暴涨 300%"这种结论多半是 1 个人变成 4 个人。日报结论只写方向性判断（如"双十二当日注册为平日 3 倍"），具体数字留给月报。这条自我约束写进报告，是专业度的直接体现。

Day 3

月报：从「多少」到「为什么」

月报不是把 30 天的日报加起来。今天练的是拆结构：增长来自哪里、质量有没有变差。

月度数据量刚好够做分析：月均注册 1,000 人左右，8 月最高 1,487，2015-12 大促 3,090。今天的核心产出是一张 12 列的月度宽表，和一篇能解释「8 月创新高是不是好事」的分析。

时段任务产出
09:00–10:30月度宽表：注册 / 活跃 / 投资 / 金额 / 复投率monthly_report.sql
10:30–12:00同环比 + 结构占比 + 金额分层扩到 15 列
14:00–15:30写 2016 年 8 月月报（一页 A4）2016-08月报.pdf
15:30–17:00补 2016-01～08 八个月的趋势图趋势图 3 张
20:00–20:30业务思考题笔记三行
SQL 练习 · 不看答案自己写
  1. 月度宽表：月新增注册、月活（App 打开去重人数）、月投资人数、月投资笔数、月交易额、月复投人数、复投率、人均投资额、人均笔数。一次 GROUP BY DATE_FORMAT(dt,'%Y-%m') 出全部。
  2. 加环比：交易额、注册量、投资人数三个指标的 LAG 环比，以及 SUM() OVER 累计值。
  3. 同期对比：2015 年 1–8 月 vs 2016 年 1–8 月，逐指标并排放。注意 2016 只有 8 个月，不要直接和 2015 全年比。
  4. 结构拆解：把月交易额按 biztype 拆成定期（1）和活期（3），算各自占比及环比变化。活期占比上升意味着什么？
  5. 金额分层：用 CASE WHEN 把单笔投资额分成 <1k / 1k–5k / 5k–2w / >2w 四档，算各档人数和金额占比。
  6. 渠道结构：算 8 月各渠道注册占比，和 7 月比，找出占比变化最大的 3 个渠道。
业务思考

8 月注册 1,487 人，是历史最高。这是好事吗？你要能用数据回答三问：新增的人有没有投资（转化率是升是降）、留下来没有（次月留存）、拉来的人贵不贵（单客首投额）。如果转化率在降而量在涨，说明什么？这条判断会直接进你报告的「核心结论」。

  • 03_月报/2016-08月报.pdf——一页 A4，含 3 个结论 + 1 个建议
  • 趋势图 3 张（注册 / 交易额 / 复投率），用 Excel 或 Python 画都行
Day 4

年报：讲一个完整的故事

年报的读者是管理层。今天练的不是取数，是「只讲三页，你讲哪三页」。

年报最容易写成流水账。判断标准：随便翻到一页，能不能用一句话说出这页想证明什么。今天两个技术重点：Cohort 留存矩阵、帕累托分析，这两个是分析师简历里的高频词，必须自己写出来过。

时段任务产出
09:00–10:30年度 KPI + 2015 vs 2016 同期对比annual_report.sql
10:30–12:00Cohort 留存矩阵（注册月 × 第 N 月）留存矩阵
14:00–15:00帕累托 + 渠道四象限2 张图
15:00–17:00年报 8–10 页，每页一句话结论年报.pptx
20:00–20:30业务思考题笔记三行
SQL 练习 · 不看答案自己写
  1. 年度 KPI 表：注册、绑卡、首投、投资人数、交易额、复投率、人均投资额，2015 全年 vs 2016 前 8 月两列并排。
  2. Cohort 留存矩阵：行是注册月，列是第 0/1/3/6/12 个月是否活跃（App 打开）。用自连接 + TIMESTAMPDIFF(MONTH, ...)，输出成可以直接贴进 Excel 做热力图的格式。
  3. 帕累托：按用户累计投资额降序，算前 1% / 5% / 10% / 20% 用户贡献的金额占比。用 SUM() OVER (ORDER BY ...) 算累计占比。
  4. 渠道四象限：横轴注册量、纵轴首投率，找出「量大质优」「量大质差」「量小质优」「量小质差」各有哪些渠道。注意：原始数据里渠道没有质量差异，必须用 Day 1 修复后的数据才算得出差别。
  5. 资金结构：按月算充值总额、提现总额、净流入，以及活期 vs 定期的持有结构变化。
  6. 增长质量表：每月新增注册 vs 该批人 30 天内的首投率，看量涨的时候质有没有掉。
业务思考

如果只能向 CEO 汇报 3 页，你选哪 3 页？提示：一页讲结果（我们做到了什么）、一页讲问题（哪里在漏）、一页讲下一步（建议做什么、看什么指标）。选完回头检查你的年报，有没有哪一页其实可以删——删不掉说明结构是对的。

今日交付物
  • 04_年报/annual_report.sql——KPI + cohort + 帕累托 + 四象限
  • 04_年报/年报.pptx——8–10 页，每页一句话标题（标题即结论）
  • 留存矩阵热力图 + 渠道四象限散点图

年报标题的写法，决定它像不像专业报告。不要写「8 月经营情况分析」，要写「8 月注册创新高，但首投转化率环比降 3 个点」。前者是目录，后者是结论。整份报告每一页标题都用这个句式，水平立刻不一样。

Day 5

Power BI：把 SQL 变成别人能点的东西

今天不写新指标，只做一件事——把前四天的结论装进三页看板，让别人不问你也能自己看。

顺序很重要：先建模，再画图。新手最常见的错误是直接拖字段画图，画到第三页发现数字对不上、筛选器联动错了，返工重来。

时段任务产出
09:00–10:00连 MySQL，Power Query 里加日期列，检查类型数据源就绪
10:00–11:30建日期表 + 星型模型 + 关系模型视图截图
11:30–12:00写 6 个基础度量值度量值列表
14:00–16:00三页看板：总览 / 渠道 / 留存3 页截图
16:00–17:00加切片器、联动、格式统一.pbix 成品
20:00–20:30业务思考题笔记三行

连接 MySQL 的两个坑。① 需要先装 MySQL Connector/NET（或改用 ODBC 数据源），否则「获取数据」里选 MySQL 会报驱动缺失；② createtime 是 datetime，直接和日期表建关系会出问题——先在 Power Query 里加一个 日期 = DateTime.Date([createtime]) 列，用它建关系。

SQL 练习 · 不看答案自己写
  1. 日期表：日期表 = CALENDAR(DATE(2015,1,1), DATE(2016,8,31))，再补年、月、年月、周几四列。标记为日期表。
  2. 六个度量值：注册用户数（DISTINCTCOUNT）、投资人数（CALCULATE + 三个筛选条件）、首投率（DIVIDE）、投资金额（四列相加）、复投率、环比（CALCULATE + DATEADD）。
  3. P1 总览页：4 个 KPI 卡（注册 / 投资人数 / 交易额 / 首投率）+ 月度趋势折线 + 年月切片器。
  4. P2 渠道页：漏斗图（注册→绑卡→首投）+ 渠道散点图（横轴注册量、纵轴首投率）+ 渠道明细表。
  5. P3 留存页：矩阵视觉对象做 cohort 热力图，行是注册月、列是第 N 月，值用条件格式上色。
  6. 统一格式：所有金额用千分位、百分比保留 1 位小数、配色不超过 3 种、每页标题写成结论句。
业务思考

这套看板是给谁看的？如果是给运营总监，他每天打开第一眼应该看到什么？如果给 CEO，第一页该砍掉哪些图？把你答案写下来，然后回去调整 P1 的布局——看板的价值不在于图多，而在于「不用解释就能看懂」。

Day 6

整合：把七天的碎片拼成一份作品

今天不写新分析，只做减法——把日/月/年三份东西合成一份 15–20 页的《P2P 理财 App 经营分析报告》。

合成不是拼贴。主报告要有一条主线：这家平台在 20 个月里靠买量做到了规模，但增长质量在下降，钱留在了少数人手里。你的三层报告都是这条主线的证据。

时段任务产出
09:00–11:00定主报告结构，写第 1–3 章（背景 / 数据 / 结论）报告骨架

30 分钟定位法（五问，固定顺序）：
① 这张表记录什么动作？（一行 = 一次注册 / 一笔交易 / 一次打开？）
② 粒度是什么？（人 · 笔 · 天 · 快照）
③ 时间范围？（决定能做同比还是只能做环比）
④ 关键状态字段有哪些枚举？（status=20 这种，决定哪些数据要排除）
⑤ 哪些字段是"因"、哪些是"果"？（时间先后能不能对上，决定能不能做转化分析）
走完这五问，你就能在纸上写出「这份数据能回答的 5 个问题」和「回答不了的 3 个问题」。

0610 个面试题自测

这周做完，这些题你应该都能用自己项目里的真实例子回答。答不上来的，就是明天要补的。

  1. 你这份数据里，最不可信的是哪个指标？为什么？
    考数据敏感度。答首投时间与注册时间的因果错位，或渠道间无差异。
  2. 留存下降，你怎么归因？
    先拆新老、再拆渠道、再看产品改动，最后才怀疑数据。
  3. 渠道 ROI 怎么算？没有成本数据怎么办？
    用首投率 × 人均首投额做质量排序，替代 ROI。
  4. 日报和月报的区别是什么？
    监控 vs 结构；异常发现 vs 归因解释。
  5. DAU 掉了 10%，你的排查顺序？
    先验数据（埋点 / 口径 / 时区），再拆维度（渠道 / 版本 / 机型），最后看外部。
  6. 怎么定义一个「活跃用户」？
    要能说出为什么选打开、而不是登录或投资。
  7. 新客首投率突然降 5 个点，你怎么查？
    分子分母分别拆，注意是不是分母被大促灌水了。
  8. 你报告里最有价值的结论是哪条？
    必须有反常识性，且能落到行动。
  9. 数据有问题但业务要上线，你怎么办？
    标注置信度、给区间、留回滚方案，别只说"不行"。
  10. 你怎么保证不同报表的口径一致？
    指标字典 + 单一数据源 + 定期对账，答到这三层就够。
